The '''Catch-Em-Turing''' (CET) function is a variant of the Busy Beaver function proposed by [[User:NathFR76|NathFR76]] in the beginning of November 2026 in forum-general<ref>In forum-general: Catch Em Turing (CET(n)) (Busy Beaver with 2 agent) post
https://discord.com/channels/960643023006490684/1377330731222564904</ref> on bbwiki discord.

Catch-Em-Turing is a variant of the Busy Beaver problem in which two independent agents operate simultaneously on a shared tape, rather than a single Turing machine head.

== Definition ==

The Catch-Em-Turing system is a computational model inspired by [[Turing machine]] and the [[Busy Beaver]] problem.

For each integer n ≥ 1, a CET(n) machine consists of:
    * Exactly 2 agents.
    * Each agent has exactly n states.
    * Each agent has its own transition table.
    * Both agents execute their transitions simultaneously.

For Configuration:
    * The tape is infinite in both directions.
    * Initially, every cell contains the symbol 0.
    * The agents are numbered Agent 1 and Agent 2.
    * Agent 1 starts at position 0. 
    * Agent 2 starts at position 2.
    * Both agents begin in their respective initial states.

At each step, each agent:
    * Reads the symbol in the cell it currently occupies.
    * Writes a symbol on that cell.
    * Moves one cell to the left or right.
    * Changes its state according to its transition table.
The agents perform these operations simultaneously.

A CET machine halts only when both agents occupy the same tape cell at the same time.
There is no individual HALT state. The collision between the two agents is the sole halting condition.
If the agents never collide, the machine does not halt.

The CET function is:

    CET(n) = '''max number of steps before collision'''

CET(n) measures the maximum number of steps that two n-state agents can execute before meeting on the same tape cell.

== Extension ==

A extension of CET(n) by [[User:NathFR76|NathFR76]] for n agent is called Multi Catch-Em-Turing, or MCET(n).

For each integer n ≥ 1, an MCET(n) machine consists of:

* Exactly n agents.
* Each agent has exactly n states.
* Each agent has its own transition table.
* All agents operate on the same infinite tape.
* All agents position is for i index the position is 2(i-1) (so: Agent 1 is at position 0, Agent 2 is at position 2, Agent 3 is at position 4, ...)
* The tape alphabet is binary, containing the symbols 0 and 1.
* All agents begin in their initial state, state 0.

At each step:

* Every agent reads the symbol in its current tape cell from the tape configuration at the beginning of that step.
* Each agent independently determines its transition.
* All writes are applied simultaneously. If multiple agents attempt to write to the same cell during the same step, the agent with the lowest index has priority.
* All agents then move one cell left or right and update their states simultaneously.

An MCET(n) machine halts only when all n agents occupy the same tape cell at the same time. There is no individual HALT state.

== Computational complexity and finite search space ==
For fixed values of n and k, the number of possible CET and MCET transition tables is finite.

Each transition is determined by three choices:

* The symbol to write: k possibilities.
* The movement direction: 2 possibilities (Left or Right).
* The next state: n possibilities.

Therefore, each state-symbol pair has exactly 2kn possible transitions.

Each agent has n states and k possible input symbols, resulting in nk transition entries per agent.

=== CET(n,k) ===
A CET machine contains exactly two agents, giving a total of 2nk transition entries.

Therefore, the total number of possible transition tables is:

<math>\mathrm{CET}(n,k) = (2kn)^{2nk}</math>

=== MCET(n,k) ===
An MCET machine contains exactly n agents, giving a total of n^2k transition entries.

Therefore, the total number of possible transition tables is:

<math>\mathrm{MCET}(n,k) = (2kn)^{n^2k}</math>

These counts assume labelled agents, deterministic transition tables, and no individual halting state. Machines are counted as distinct whenever at least one transition entry differs.

The finite search space makes exhaustive enumeration theoretically possible for every fixed pair (n,k), although the number of machines grows extremely rapidly.
