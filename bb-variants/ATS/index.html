ATS rules used by this simulator

A token is a primitive bit 0/1 or a function fn(alpha) with non-empty binary alpha. One step is absorption, then head execution. The head is always the first token; the tape is a FIFO queue.

  1. Absorb: scan left-to-right. An internal function followed by a primitive absorbs that bit into its argument and removes the primitive. Keep scanning at the same function through a run of primitives.
  2. Execute the first token: 0 does nothing. 1 copies the next two tokens to the tail. fn(alpha) with no 1 behaves like 0; fn(1) behaves like 1; a composite uses the zero-rule (delete the last token) and one-rule (append fn(1) and the shortened argument) in count-dependent order.
  3. Halt when the queue becomes empty. A step counts once per head execution, even if absorption did nothing.

Exact reference semantics live in ats.py; this browser tool is intended for exploration, not proof checking.

Reading the diagram

Whole tape samples the complete queue into columns; this is the right default for Grove, whose token count grows past 10,000.

Head window shows the first 400 tokens, where the next execution happens. Tail window shows where copies and the zero-rule land.

Colors encode token classes, not token identity. A row can therefore hold many fn(1) tokens without drawing every one.

The diagram is a visualization of the ATS queue, not a Turing-machine tape: there is no moving head, only the queue front.
